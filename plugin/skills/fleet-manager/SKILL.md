# fleet-manager

Multi-server SSH management. The plugin persists a per-server inventory and an
"active server" pointer across sessions, so commands can be run without naming a
host every time.

## State Locations

State lives in `$FM_CONTEXT`, which resolves to `$FM_CONTEXT_DIR` if set, else
`${XDG_CONFIG_HOME:-~/.config}/fleet-manager`. It is deliberately outside the
plugin directory: that directory is version-pinned and replaced wholesale on
`claude plugin update`.

| What | Where | Notes |
| - | - | - |
| Active server | `$FM_CONTEXT/active-server` | Single source of truth; written by `set_active` |
| Inventory | `$FM_CONTEXT/inventory.md` | Regenerated by `write_inventory` |
| Server profiles | `$FM_CONTEXT/servers/<name>.md` | Hosts, users, ports, scopes, discovered state |
| Plugin SSH key | `~/.ssh/fleet-manager_ed25519` | Deployed per server via `/setup-ssh` |

None of this is committed — the real topology never lands in git. Inspect the
inventory with `/list-servers`, never by reading hostnames out of this file.

## Available Commands

| Command | Description |
| - | - |
| `/first-run` | Onboard your first server (interactive intake agent) |
| `/add-server` | Add another server to the inventory |
| `/list-servers` | Show the inventory; mark the active server |
| `/use <name>` | Set the active server |
| `/setup-ssh [server]` | Generate the plugin keypair and deploy it (idempotent) |
| `/diag [server]` | Connectivity + health check (SSH, sudo, docker, disk, load) |
| `/status [server]` | Disk / memory / uptime / load snapshot |
| `/compose-list [server]` | List Compose projects |
| `/docker-list [server] [--all]` | List containers |
| `/compose-logs [server] <project>` | Compose logs |
| `/compose-up [server] <project\|--file path>` | Start a stack |
| `/compose-down [server] <project> [--remove]` | Stop a stack (critical → `--confirm`) |
| `/compose-update [server] <project>` | Pull + recreate |
| `/logs [server] [unit]` | System journal (journalctl/syslog) |
| `/health-summary` | Fleet-wide health (one row per server) |
| `/copy <src> <dst>` | Copy local↔server (rsync/scp) |
| `/sync <src> <dst> [--apply]` | Mirror local↔server (dry-run default) |

## Scoped Operations

Each server profile carries its own authorized categories: `system_monitoring`,
`file_operations`, `package_management`, `service_management`, `docker_compose`,
`file_transfer`.

**Enforced** for compose commands (`docker_compose`) and `/logs`
(`system_monitoring`) — a command refuses if its scope is unticked. Ad-hoc SSH
remains **advisory**: honor scopes and protected resources before running
destructive commands.

Destructive compose actions against `critical_compose_projects` require a
matching `--confirm=<project>` token.

## Operational Guidelines

### Before Operations

1. Resolve the target: an explicit argument wins, else the active server.
2. **Always confirm the target** — every command prints `→ Ziel: <name> (user@host:port)` first.
3. Check the server's profile for authorized scopes and protected resources.

### During Operations

1. Use SSH via the `FM_SSH=(...)` array from `_fleet-lib.sh` — never string-interpolate.
2. Prefer non-destructive operations (list before delete, backup before modify).
3. For destructive actions against `critical_compose_projects` or `protected_paths`,
   confirm the server name and the resource explicitly before proceeding.

### After Operations

1. Update the profile's "Discovered State" when state changes.
2. Regenerate `inventory.md` after inventory changes (`write_inventory`).

## Common Mistakes

| Mistake | Consequence |
| - | - |
| Mirroring the active server into a tracked file | Dirties the working tree on every `/use` and is lost on `plugin update` |
| Deriving a state path from `$CLAUDE_PLUGIN_ROOT` | That path is version-pinned; the inventory is stranded on the next update. Use `$FM_CONTEXT` |
| Reading `context/active-server` directly | Bypasses validation; use `resolve_server` (rejects path traversal) |
| Interpolating host/user into an `ssh` string | Breaks on unusual ports and quoting; use the `FM_SSH` array |
| Running `ssh-copy-id` on the user's behalf | Key deployment is presented as copy-paste, never executed by the agent |
